# SPR kernels: runtime and roofline

- CPU **Apple M4 Pro**, threads **1**, ISA `neon`; kernels: `spr.naive`, `spr.v0`, `spr.v1`, `spr.v2.b32`, `spr.v3.b32.u1`, `spr.v4.b32`, `spr.v5.b32`
- speed-ups are vs **`spr.naive`** (> 1 = faster); every number is the kernel's best k for that shape / sparsity

## 1. Machine ceilings (measured by `build/peaks`)

| ceiling | measured | datasheet |
|---|---|---|
| fp32 add, SIMD | 66.8 GFLOP/s | - |
| fp32 add, scalar | 17.9 GFLOP/s | - |
| read BW, L1 | 191 GB/s | - |
| read BW, L2 | 117 GB/s | - |
| read BW, DRAM | 96 GB/s | - |

Ridge point (SIMD peak / DRAM BW): **0.69 flop/byte**: a kernel with lower intensity is DRAM-bound at best, higher intensity can reach the compute peak.

## 3. Roofline position (best k)

- **GFLOP/s** = additions per second; **AI** = additions / compulsory bytes (format + X + Y)
- **% scalar / % SIMD** = fraction of the scalar / SIMD add peak; **% roof** = fraction of min(SIMD peak, AI × DRAM BW)
- **re-read GB/s** = format bytes × M / time: the bandwidth needed if the format is streamed once per row of X (compare with L2 117 / DRAM 96 GB/s)

# SPR kernels: runtime and roofline

- CPU **Apple M4 Pro**, threads **14**, ISA `neon`; kernels: `spr.v2.b32`, `spr.v4.b32`, `spr.v5.b32`
- speed-ups are vs **`spr.v4.b32`** (> 1 = faster); every number is the kernel's best k for that shape / sparsity

## 1. Machine ceilings (measured by `build/peaks`)

| ceiling | measured | datasheet |
|---|---|---|
| fp32 add, SIMD | 595.1 GFLOP/s | - |
| fp32 add, scalar | 154.9 GFLOP/s | - |
| read BW, L1 | 1641 GB/s | - |
| read BW, L2 | 947 GB/s | - |
| read BW, DRAM | 243 GB/s | - |

Ridge point (SIMD peak / DRAM BW): **2.45 flop/byte**: a kernel with lower intensity is DRAM-bound at best, higher intensity can reach the compute peak.

## 5. Insights

- `spr.v2.b32`: 11% of the scalar add peak, 3% of the SIMD peak, 3% of the roofline (geomean). 0/16 points sit left of the ridge (DRAM-bound roof).
  - Far below every ceiling: neither DRAM bandwidth nor the add units are the limit. The time goes into latency: index loads, gathers, short loops with data-dependent trip counts (branch mispredicts).
- `spr.v4.b32`: 16% of the scalar add peak, 4% of the SIMD peak, 4% of the roofline (geomean). 0/16 points sit left of the ridge (DRAM-bound roof).
  - Far below every ceiling: neither DRAM bandwidth nor the add units are the limit. The time goes into latency: index loads, gathers, short loops with data-dependent trip counts (branch mispredicts).
  - ns/add rises strongly with k in 15/16 cases: larger k saves additions but each one costs more.
- `spr.v5.b32`: 16% of the scalar add peak, 4% of the SIMD peak, 4% of the roofline (geomean). 0/16 points sit left of the ridge (DRAM-bound roof).
  - Far below every ceiling: neither DRAM bandwidth nor the add units are the limit. The time goes into latency: index loads, gathers, short loops with data-dependent trip counts (branch mispredicts).
  - ns/add rises strongly with k in 16/16 cases: larger k saves additions but each one costs more.

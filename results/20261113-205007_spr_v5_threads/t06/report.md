# SPR kernels: runtime and roofline

- CPU **Apple M4 Pro**, threads **6**, ISA `neon`; kernels: `spr.v2.b32`, `spr.v4.b32`, `spr.v5.b32`
- speed-ups are vs **`spr.v4.b32`** (> 1 = faster); every number is the kernel's best k for that shape / sparsity

## 1. Machine ceilings (measured by `build/peaks`)

| ceiling | measured | datasheet |
|---|---|---|
| fp32 add, SIMD | 370.3 GFLOP/s | - |
| fp32 add, scalar | 93.5 GFLOP/s | - |
| read BW, L1 | 1077 GB/s | - |
| read BW, L2 | 639 GB/s | - |
| read BW, DRAM | 243 GB/s | - |

Ridge point (SIMD peak / DRAM BW): **1.52 flop/byte**: a kernel with lower intensity is DRAM-bound at best, higher intensity can reach the compute peak.

- **re-read GB/s** = format bytes × M / time: the bandwidth needed if the format is streamed once per row of X (compare with L2 639 / DRAM 243 GB/s)

## 5. Insights

- `spr.v2.b32`: 19% of the scalar add peak, 5% of the SIMD peak, 5% of the roofline (geomean). 0/16 points sit left of the ridge (DRAM-bound roof).
  - Far below every ceiling: neither DRAM bandwidth nor the add units are the limit. The time goes into latency: index loads, gathers, short loops with data-dependent trip counts (branch mispredicts).
- `spr.v4.b32`: 27% of the scalar add peak, 7% of the SIMD peak, 7% of the roofline (geomean). 0/16 points sit left of the ridge (DRAM-bound roof).
  - Far below every ceiling: neither DRAM bandwidth nor the add units are the limit. The time goes into latency: index loads, gathers, short loops with data-dependent trip counts (branch mispredicts).
  - ns/add rises strongly with k in 15/16 cases: larger k saves additions but each one costs more.
- `spr.v5.b32`: 27% of the scalar add peak, 7% of the SIMD peak, 7% of the roofline (geomean). 0/16 points sit left of the ridge (DRAM-bound roof).
  - Far below every ceiling: neither DRAM bandwidth nor the add units are the limit. The time goes into latency: index loads, gathers, short loops with data-dependent trip counts (branch mispredicts).
  - ns/add rises strongly with k in 15/16 cases: larger k saves additions but each one costs more.

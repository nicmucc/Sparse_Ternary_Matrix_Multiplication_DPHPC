# SPR kernels: runtime and roofline

- CPU **Apple M4 Pro**, threads **2**, ISA `neon`; kernels: `spr.v5.b32`, `spr.v6.b32`
- speed-ups are vs **`spr.v5.b32`** (> 1 = faster); every number is the kernel's best k for that shape / sparsity

## 1. Machine ceilings (measured by `build/peaks`)

| ceiling | measured | datasheet |
|---|---|---|
| fp32 add, SIMD | 135.2 GFLOP/s | - |
| fp32 add, scalar | 34.4 GFLOP/s | - |
| read BW, L1 | 375 GB/s | - |
| read BW, L2 | 223 GB/s | - |
| read BW, DRAM | 162 GB/s | - |

Ridge point (SIMD peak / DRAM BW): **0.84 flop/byte**: a kernel with lower intensity is DRAM-bound at best, higher intensity can reach the compute peak.

## 3. Roofline position (best k)

- **re-read GB/s** = format bytes × M / time: the bandwidth needed if the format is streamed once per row of X (compare with L2 223 / DRAM 162 GB/s)

## 5. Insights

- `spr.v5.b32`: 118% of the scalar add peak, 30% of the SIMD peak, 30% of the roofline (geomean). 1/20 points sit left of the ridge (DRAM-bound roof).
  - Format re-read traffic reaches 113 GB/s (4096×1024, s=70%), 51% of L2 bandwidth: streaming the format once per row of X is a real cost. Reading it once per block (block-outer loop, M-tile inner) removes it.
  - ns/add rises strongly with k in 17/20 cases: larger k saves additions but each one costs more.
- `spr.v6.b32`: 116% of the scalar add peak, 29% of the SIMD peak, 30% of the roofline (geomean). 1/20 points sit left of the ridge (DRAM-bound roof).
  - ns/add rises strongly with k in 12/20 cases: larger k saves additions but each one costs more.

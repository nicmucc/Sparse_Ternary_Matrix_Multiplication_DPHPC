# SPR kernels: runtime and roofline

- CPU **Apple M4 Pro**, threads **14**, ISA `neon`; kernels: `spr.v5.b32`, `spr.v6.b32`
- speed-ups are vs **`spr.v5.b32`** (> 1 = faster); every number is the kernel's best k for that shape / sparsity

## 1. Machine ceilings (measured by `build/peaks`)

| ceiling | measured | datasheet |
|---|---|---|
| fp32 add, SIMD | 618.3 GFLOP/s | - |
| fp32 add, scalar | 154.4 GFLOP/s | - |
| read BW, L1 | 1877 GB/s | - |
| read BW, L2 | 1091 GB/s | - |
| read BW, DRAM | 248 GB/s | - |

Ridge point (SIMD peak / DRAM BW): **2.49 flop/byte**: a kernel with lower intensity is DRAM-bound at best, higher intensity can reach the compute peak.

## 3. Roofline position (best k)

- **re-read GB/s** = format bytes × M / time: the bandwidth needed if the format is streamed once per row of X (compare with L2 1091 / DRAM 248 GB/s)

## 5. Insights

- `spr.v5.b32`: 59% of the scalar add peak, 15% of the SIMD peak, 16% of the roofline (geomean). 2/20 points sit left of the ridge (DRAM-bound roof).
  - Far below every ceiling: neither DRAM bandwidth nor the add units are the limit. The time goes into latency: index loads, gathers, short loops with data-dependent trip counts (branch mispredicts).
  - ns/add rises strongly with k in 14/20 cases: larger k saves additions but each one costs more.
- `spr.v6.b32`: 51% of the scalar add peak, 13% of the SIMD peak, 14% of the roofline (geomean). 2/20 points sit left of the ridge (DRAM-bound roof).
  - Far below every ceiling: neither DRAM bandwidth nor the add units are the limit. The time goes into latency: index loads, gathers, short loops with data-dependent trip counts (branch mispredicts).
  - ns/add rises strongly with k in 11/20 cases: larger k saves additions but each one costs more.

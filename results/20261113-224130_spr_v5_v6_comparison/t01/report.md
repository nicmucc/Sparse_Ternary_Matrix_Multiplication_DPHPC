# SPR kernels: runtime and roofline

- CPU **Apple M4 Pro**, threads **1**, ISA `neon`; kernels: `spr.v5.b32`, `spr.v6.b32`
- speed-ups are vs **`spr.v5.b32`** (> 1 = faster); every number is the kernel's best k for that shape / sparsity

## 1. Machine ceilings (measured by `build/peaks`)

| ceiling | measured | datasheet |
|---|---|---|
| fp32 add, SIMD | 71.9 GFLOP/s | - |
| fp32 add, scalar | 17.9 GFLOP/s | - |
| read BW, L1 | 206 GB/s | - |
| read BW, L2 | 124 GB/s | - |
| read BW, DRAM | 96 GB/s | - |

Ridge point (SIMD peak / DRAM BW): **0.75 flop/byte**: a kernel with lower intensity is DRAM-bound at best, higher intensity can reach the compute peak.

## 3. Roofline position (best k)

- **GFLOP/s** = additions per second; **AI** = additions / compulsory bytes (format + X + Y)
- **% scalar / % SIMD** = fraction of the scalar / SIMD add peak; **% roof** = fraction of min(SIMD peak, AI × DRAM BW)
- **re-read GB/s** = format bytes × M / time: the bandwidth needed if the format is streamed once per row of X (compare with L2 124 / DRAM 96 GB/s)

## 5. Insights

- `spr.v5.b32`: 145% of the scalar add peak, 36% of the SIMD peak, 36% of the roofline (geomean). 0/20 points sit left of the ridge (DRAM-bound roof).
  - ns/add rises strongly with k in 14/20 cases: larger k saves additions but each one costs more.
- `spr.v6.b32`: 144% of the scalar add peak, 36% of the SIMD peak, 36% of the roofline (geomean). 0/20 points sit left of the ridge (DRAM-bound roof).
  - ns/add rises strongly with k in 15/20 cases: larger k saves additions but each one costs more.

# SPR kernels: runtime and roofline

- CPU **Apple M4 Pro**, threads **12**, ISA `neon`; kernels: `spr.v5.b32`, `spr.v6.b32`
- speed-ups are vs **`spr.v5.b32`** (> 1 = faster); every number is the kernel's best k for that shape / sparsity

## 1. Machine ceilings (measured by `build/peaks`)

| ceiling | measured | datasheet |
|---|---|---|
| fp32 add, SIMD | 583.9 GFLOP/s | - |
| fp32 add, scalar | 147.3 GFLOP/s | - |
| read BW, L1 | 1600 GB/s | - |
| read BW, L2 | 978 GB/s | - |
| read BW, DRAM | 243 GB/s | - |

Ridge point (SIMD peak / DRAM BW): **2.40 flop/byte**: a kernel with lower intensity is DRAM-bound at best, higher intensity can reach the compute peak.

## 3. Roofline position (best k)

- **GFLOP/s** = additions per second; **AI** = additions / compulsory bytes (format + X + Y)
- **% scalar / % SIMD** = fraction of the scalar / SIMD add peak; **% roof** = fraction of min(SIMD peak, AI × DRAM BW)
- **re-read GB/s** = format bytes × M / time: the bandwidth needed if the format is streamed once per row of X (compare with L2 978 / DRAM 243 GB/s)

## 5. Insights

- `spr.v5.b32`: 61% of the scalar add peak, 15% of the SIMD peak, 16% of the roofline (geomean). 2/20 points sit left of the ridge (DRAM-bound roof).
  - Far below every ceiling: neither DRAM bandwidth nor the add units are the limit. The time goes into latency: index loads, gathers, short loops with data-dependent trip counts (branch mispredicts).
  - ns/add rises strongly with k in 14/20 cases: larger k saves additions but each one costs more.
- `spr.v6.b32`: 52% of the scalar add peak, 13% of the SIMD peak, 14% of the roofline (geomean). 3/20 points sit left of the ridge (DRAM-bound roof).
  - Far below every ceiling: neither DRAM bandwidth nor the add units are the limit. The time goes into latency: index loads, gathers, short loops with data-dependent trip counts (branch mispredicts).
  - ns/add rises strongly with k in 11/20 cases: larger k saves additions but each one costs more.

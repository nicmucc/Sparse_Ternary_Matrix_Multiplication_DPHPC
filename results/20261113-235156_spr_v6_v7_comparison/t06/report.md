# SPR kernels: runtime and roofline

- CPU **Apple M4 Pro**, threads **6**, ISA `neon`; kernels: `spr.v6.b32`, `spr.v7.b32`
- speed-ups are vs **`spr.v6.b32`** (> 1 = faster); every number is the kernel's best k for that shape / sparsity

## 1. Machine ceilings (measured by `build/peaks`)

| ceiling | measured | datasheet |
|---|---|---|
| fp32 add, SIMD | 372.3 GFLOP/s | - |
| fp32 add, scalar | 93.0 GFLOP/s | - |
| read BW, L1 | 1052 GB/s | - |
| read BW, L2 | 651 GB/s | - |
| read BW, DRAM | 236 GB/s | - |

Ridge point (SIMD peak / DRAM BW): **1.58 flop/byte**: a kernel with lower intensity is DRAM-bound at best, higher intensity can reach the compute peak.

## 3. Roofline position (best k)

- **GFLOP/s** = additions per second; **AI** = additions / compulsory bytes (format + X + Y)
- **% scalar / % SIMD** = fraction of the scalar / SIMD add peak; **% roof** = fraction of min(SIMD peak, AI × DRAM BW)
- **re-read GB/s** = format bytes × M / time: the bandwidth needed if the format is streamed once per row of X (compare with L2 651 / DRAM 236 GB/s)

## 5. Insights

- `spr.v6.b32`: 76% of the scalar add peak, 19% of the SIMD peak, 20% of the roofline (geomean). 1/20 points sit left of the ridge (DRAM-bound roof).
  - Far below every ceiling: neither DRAM bandwidth nor the add units are the limit. The time goes into latency: index loads, gathers, short loops with data-dependent trip counts (branch mispredicts).
- `spr.v7.b32`: 70% of the scalar add peak, 18% of the SIMD peak, 18% of the roofline (geomean). 1/20 points sit left of the ridge (DRAM-bound roof).
  - Far below every ceiling: neither DRAM bandwidth nor the add units are the limit. The time goes into latency: index loads, gathers, short loops with data-dependent trip counts (branch mispredicts).

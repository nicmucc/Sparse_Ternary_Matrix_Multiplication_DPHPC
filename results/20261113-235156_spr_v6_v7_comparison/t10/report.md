# SPR kernels: runtime and roofline

- CPU **Apple M4 Pro**, threads **10**, ISA `neon`; kernels: `spr.v6.b32`, `spr.v7.b32`
- speed-ups are vs **`spr.v6.b32`** (> 1 = faster); every number is the kernel's best k for that shape / sparsity

## 1. Machine ceilings (measured by `build/peaks`)

| ceiling | measured | datasheet |
|---|---|---|
| fp32 add, SIMD | 611.0 GFLOP/s | - |
| fp32 add, scalar | 153.3 GFLOP/s | - |
| read BW, L1 | 1592 GB/s | - |
| read BW, L2 | 1029 GB/s | - |
| read BW, DRAM | 244 GB/s | - |

Ridge point (SIMD peak / DRAM BW): **2.51 flop/byte**: a kernel with lower intensity is DRAM-bound at best, higher intensity can reach the compute peak.

## 3. Roofline position (best k)

- **GFLOP/s** = additions per second; **AI** = additions / compulsory bytes (format + X + Y)
- **% scalar / % SIMD** = fraction of the scalar / SIMD add peak; **% roof** = fraction of min(SIMD peak, AI × DRAM BW)
- **re-read GB/s** = format bytes × M / time: the bandwidth needed if the format is streamed once per row of X (compare with L2 1029 / DRAM 244 GB/s)

## 5. Insights

- `spr.v6.b32`: 63% of the scalar add peak, 16% of the SIMD peak, 17% of the roofline (geomean). 4/20 points sit left of the ridge (DRAM-bound roof).
  - Far below every ceiling: neither DRAM bandwidth nor the add units are the limit. The time goes into latency: index loads, gathers, short loops with data-dependent trip counts (branch mispredicts).
- `spr.v7.b32`: 54% of the scalar add peak, 14% of the SIMD peak, 15% of the roofline (geomean). 4/20 points sit left of the ridge (DRAM-bound roof).
  - Far below every ceiling: neither DRAM bandwidth nor the add units are the limit. The time goes into latency: index loads, gathers, short loops with data-dependent trip counts (branch mispredicts).
